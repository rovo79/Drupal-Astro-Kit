<task type="auto">
  <name>Task 1: Create docs/publishing.md</name>
  <files>docs/publishing.md</files>
  <action>
    Create `docs/publishing.md` — the standalone publishing workflow doc. This doc explains the *model*, not just the commands (deployment.md already covers commands in detail).

    Structure and content guidance:

    1. **Title and opening**: "Publishing Workflow" — one-sentence summary: editing content in Drupal does not automatically update the live site; you rebuild and deploy.

    2. **The Mental Model** section:
       - Static-first means the live site is pre-rendered HTML. Drupal is the *authoring* tool, not the *serving* tool.
       - "Publishing" in Drupal marks content as ready. Getting it live requires a rebuild.
       - This is by design: it gives you control over exactly what goes live and when.
       - Use a simple diagram/flow:
         ```
         Edit in Drupal → Save/Publish → Rebuild Astro → Deploy to Pages → Live
         ```

    3. **Why Rebuild-to-Publish?** section (the tradeoff statement — this is a PUBL-02 requirement):
       - Frame as a deliberate choice, not a limitation
       - Benefits: control over what's live, zero runtime dependencies, no accidental publishes, full preview before deploy, simple hosting
       - Tradeoff: content isn't instant — you run a command. For a starter kit aimed at developers, this is a feature (you control the deploy), not a bug.
       - Contrast briefly with the alternative (SSR/live CMS) and why this kit chose differently

    4. **Step-by-Step** section:
       - Step 1: Edit content in Drupal (at `http://<project>.ddev.site/admin/content`)
       - Step 2: Rebuild the site — copy-pasteable commands:
         ```bash
         cd drupal-backend && ddev start    # Ensure Drupal is running
         cd ../astro-frontend && npm run build
         ```
       - Step 3: Deploy — copy-pasteable commands:
         ```bash
         ./scripts/deploy-frontend.sh
         ```
         Or manual:
         ```bash
         cd astro-frontend
         npx wrangler pages deploy ./dist --project-name=your-project
         ```

    5. **Quick Reference** section — a compact cheat sheet:
       ```
       # The full publish cycle in three commands:
       cd drupal-backend && ddev start
       cd ../astro-frontend && npm run build
       cd .. && ./scripts/deploy-frontend.sh
       ```

    6. **When You Need More** section — brief pointer to docs/future/ for SSR, CI/CD, etc. One sentence, one link. Don't elaborate — just acknowledge it exists.

    7. **See Also** — link to `deployment.md` for deployment details, `architecture.md` for how components connect.

    Tone: Direct, developer-friendly. No apology for the rebuild model — frame it as a feature of static-first.
    Length: ~80-120 lines. Concise. Not a tutorial — a mental model + workflow reference.

    Do NOT duplicate the full deployment setup (first-time Cloudflare setup, env vars, troubleshooting) — that lives in deployment.md. This doc is about the *publishing model* and the *workflow*, with commands for the common case.
